# How Tremors works

Tremors is a Windows tray application of about 750 lines of C#, comments included. This page explains the
mechanism and the filter, so that anyone can check, tune or improve it.

## Intercepting the mouse

Tremors installs a global low-level mouse hook (`SetWindowsHookEx` with `WH_MOUSE_LL`).
Windows then calls Tremors for every physical mouse event *before* any window receives it.

Changing the position inside such a hook has no effect: Windows ignores it. So for every
movement Tremors does this instead:

0. While filtering, Windows mouse acceleration ("Enhance pointer precision") is switched
   off for the session. Acceleration enlarges fast movements,
   and trembling is fast, so shakes would otherwise reach the filter magnified. The
   change is not saved to the user profile and is undone on pause or exit.
1. Read where Windows *would* put the cursor (`pt` in the event) and where it is now.
   The difference is the movement of the hand, including the user's pointer speed and
   acceleration settings.
2. Swallow the event, so the cursor does not move by itself.
3. Compute a steady position and move the cursor there with `SetCursorPos`.

Clicks, wheel and keyboard are never delayed. Events generated by software
(remote desktop, on-screen keyboards, `SendInput`) carry the `LLMHF_INJECTED` flag and
pass through untouched.

## The filter

The filter keeps these positions:

```
raw     where the hand is: the sum of all swallowed movement, times the pointer speed
mid     first filter stage
smooth  second filter stage
cursor  what is on screen
```

### 1. Intent

A tremor, even a sudden jerk of several centimetres, goes back and forth or stops
after a fraction of a second. A deliberate movement keeps going in one direction. So
Tremors does not look at how *far* the hand moved, but at how *fast it keeps moving*:
the hand velocity averaged over 250 ms.

```
velocity = average of (raw movement / time) over 250 ms
intent   = max(0, |velocity| - 0.5 px/ms) / 0.2 px/ms
```

Below 0.5 px/ms (about 13 cm per second on a typical screen, averaged) movement counts
as tremor and gets the full filter. A jerk that goes out and comes back averages out to
almost nothing. Only a sustained movement builds up intent.

### 2. Adaptive two-stage low-pass

On every event, and on a 10 ms timer while the cursor is still catching up, the two
stages move towards `raw`:

```
tau    = T / (1 + intent) / 2
a      = 1 - exp(-dt / tau)
mid    = mid    + a * (raw - mid)
smooth = smooth + a * (mid - smooth)
```

`T` is the time constant: up to 500 ms at strength 100 (`T = 500 ms * k^1.5`, with
`k = strength / 100`). Because the filter works in time, not per event, it behaves the
same on a 125 Hz office mouse and a 1000 Hz gaming mouse.

Two stages in series damp a sudden jerk much more than a single stage with the same
delay. With intent, `tau` drops and the cursor catches up quickly. That keeps
Tremors from feeling sluggish while still absorbing jerks.

### 3. Leash

The cursor is tied to `smooth` with a leash: the **still zone** setting, 4 px by
default and up to 30 px. While `smooth` stays within the leash, the cursor does not move
at all. Once it moves further, the cursor follows it at leash distance. A small zone
removes the last pixel of wobble when holding still on a target; a larger zone also
absorbs bigger jerks, at the cost of having to move a little further before the cursor
starts to follow (the "lazy mouse" or "pulled string" technique from drawing tools).

### 4. Click

On a button press the remaining glide is dropped (`raw`, `mid`, `smooth` and the velocity jump to the cursor),
so the cursor does not drift while clicking or double-clicking.

### 5. Hold to click

With **hold to click** set (for example 150 ms), a physical button-down is swallowed and
the cursor stays put. If the button is released sooner, the click is dropped: a
trembling tap. If it is still down after the hold time, Tremors sends the button-down
to Windows itself (`SendInput`), and the physical button-up later passes normally. So:

- dragging works: the button stays down for as long as the user holds it;
- double-clicking works: both clicks are delayed by the same amount, so the interval
  between them is unchanged;
- each button (left, right, middle) is handled on its own.

### 6. Scroll wheel

A tremor often turns the wheel one notch forward and immediately back. Tremors drops a
notch in the opposite direction when it comes within `400 ms * k` of the previous notch.
A real change of direction after that pause passes normally.

### Staying correct

- If another program moves the cursor (a dialog that centres it, a remote session),
  Tremors notices that the cursor is not where it left it and starts again from there.
- `raw` is clamped to the desktop, so pushing into a screen edge does not build up an
  invisible offset.
- At strength 0 nothing is filtered and every event passes through unchanged.

## Measured effect

The tests in [`tests/Tremors.Tests`](../tests/Tremors.Tests/SmootherTests.cs) simulate a
125 Hz mouse. Two situations while the user tries to hold still:

- **Tremor:** a continuous 5 Hz essential tremor of ±8 px (16 px wide).
- **Jerk:** a sudden jerk of 150 px (about 4 cm) out in 64 ms and back in 96 ms.

And one deliberate movement of 600 px in 0.3 s, measuring how long the cursor needs
after the hand stops.

| Strength | Tremor left | Jerk left | Deliberate move settles in |
|---|---|---|---|
| off | 16 px | 150 px | 0 s |
| 30 | 4 px | 80 px | 0.02 s |
| 50 | 0 px | 45 px | 0.07 s |
| 70 (default) | 0 px | 27 px | 0.24 s |
| 85 | 0 px | 19 px | 0.6 s |
| 100 | 0 px | 14 px | 1.1 s |

The tests also check that deliberate movements end on target, also with tremor on
top, that clicks stop the glide and that the wheel filter lets real reversals through.

## Tuning

The constants are in `Smoother.Tuning` at the top of [`Smoother.cs`](../src/Tremors/Smoother.cs); tests can pass their own. If you
change them, run `dotnet test` and, more importantly, try it with someone who has a
tremor. Feedback from real use is the most valuable contribution there is.
